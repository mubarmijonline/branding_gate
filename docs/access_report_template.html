What the sweep found

The sales request page was rendering an empty shellfixed

Its body gate still tested legacy role names — 'sales' in user_roles — while the role codes are now sales_member and sales_head. Every non-admin role received the page with no header and no table, just the surrounding shell. This is the page Sales works in all day. Eighteen further card-level gates across the admin, finance and sales sections had the same fault and are converted too; no template tests a role name any more.

Pricing controls were hidden from Pricing itselffixed

CAN_CONTROL_PRICING tested 'pricing' in user_roles against the role code pricing_manager, so the set-price modal and every pricing control were invisible to everyone — Pricing Manager included. It now reads the permission directly.

Supplier report Excel export returned a 500 for everyonefixed

The handler rebuilds its data by calling the report endpoint inside a fresh request context, then copied the session across after entering it — where session already pointed at the new, empty one. The inner call saw an anonymous caller and refused. The snapshot is taken first now, and the export returns a real workbook.

Two catalog endpoints queried columns that do not existfixed

/api/sales-requests/catalog/items and /catalog/item-types failed for every role including Admin, reading item_name and item_type_id from a table that has item_label and no type column. Both now match the shipped schema. They return an empty list because those tables are empty — confirmed correct by inserting a type, an item and two descriptions inside a rolled-back transaction and watching them come back grouped.

Client detail failed on a missing tablefixed

/api/clients/<id> joined a parent_company table that does not exist. It joins company now, which the client list and the add/edit validation already used.

A missing file reported as a server errorfixed

/api/sales/requests/files/<id>/download calls abort(404) when a file is absent, but its own blanket except Exception caught that and re-raised it as a 500. It re-raises HTTPException first now. The same pattern was in subscribe(); a scan confirmed no other handler swallows an abort this way.

The probe itself was passing a broken pagemethod

The first sweep marked the sales request page as working, because it only looked for access-denied strings and short bodies — and a gated-out page still ships 766 KB of scripts. The classifier now checks whether the page rendered any content of its own: a card, table, heading or form. That is what caught the empty shell, and the numbers on this page are from the corrected run.

Four roles can open the admin landing pageby design

Assistant, Sales Head, Account Director and Account Team Leader reach /management_admin because it admits anyone holding client, company, supplier or entity editing rights, and they manage clients. The cards inside are gated separately, so they see only what they can use.

Assistant can open the users pagecheck this

The Assistant holds user.view so it can read the directory, but not user.create, edit or delete — those buttons all answer 403. If the Assistant should not see staff records at all, drop user.view from the role in rbac.py.

Pricing is a flag, not only a role

Pricing does not follow the org chart, so any account can be marked as pricing from the users page regardless of its role. The flag grants selling-price entry, the pricing dashboard and the negotiation pricing decision — either the Pricing roles or the flag is enough. Its scope is deliberately company-wide: someone who prices has to reach every request, not only the ones their own role would show them. Nobody without it sees any pricing control.
