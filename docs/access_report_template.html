What each role can actually reach

Every role was given a real account wired into a reporting line, then used to request every readable route in the application. It now runs as the real organisation — one person per role, drawn from the live chart — so what each row sees reflects the actual reporting line, not a test account with no reports. An HTTP 200 was not taken as proof: pages that return 200 while rendering their access-denied branch are counted as blocked, and JSON replies carrying success: false are counted as broken.

What the sweep found

No broken endpoints and no unexpected refusals. Every non-OK result below is either a correct denial, a redirect the application means to make, or a request for a row that does not exist yet.

The users page was inert in the browserfixed

Removing the legacy roles UI with a line-oriented pattern had matched the opening line of a multi-line handler and stopped there, deleting $('#addUserModal').on(...) while leaving its body and closing brace. That closed $(document).ready early and left one brace too many, so the browser aborted the whole script and nothing on the page worked. The page still returned 200 and still rendered, which is why an earlier sweep passed it. Every template's inline JavaScript is now syntax-checked by a test.

The sales request page rendered an empty shellfixed

Its body gate still tested legacy role names, so every non-admin role received the page with no header and no table. Eighteen further card-level gates had the same fault. No template tests a role name any more, and the page now opens for 20 of the 21 roles.

Pricing controls were hidden from Pricing itselffixed

CAN_CONTROL_PRICING compared against the old role string, so the set-price modal was invisible to everyone including Pricing Manager. It reads the permission directly now.

Four endpoints returned a 500 on every requestfixed

The supplier-report Excel export copied its session into an inner request context after entering it, so the internal call saw an anonymous caller. Two catalog endpoints queried columns that never shipped. Client detail joined a parent_company table that does not exist. A missing file reported as a server error because abort(404) was swallowed by the handler's own blanket exception catch.

Teams have been retiredchanged

Teams granted no access once the permission model landed, and department plus reporting line replaces them. The Teams card, the team endpoints and the three team.* permissions are gone; the table and column remain untouched so nothing is lost.

The probe was reporting its own gaps as failuresmethod

It filled URL parameters with a hardcoded 1, so routes whose row happened to have another id came back 404 and looked broken — /api/companies/documents/1/download among them, where document 4 answers 200. It resolves real ids from the database now and skips routes whose table is empty, since a 404 there says nothing about access.

The Assistant sees every sales requestdecide this

Running the sweep against the real organisation rather than throwaway accounts made this visible: assistant holds sales_request.view at company-wide scope, so it reads all 25 requests. The brief said the Assistant should have no automatic access to all company data. Narrowing it to department would confine it to the Executive department, which holds only the CEO and the Assistant — effectively nothing. Say the word and it changes in one line of rbac.py.

Four roles can open the admin landing pageby design

Assistant, Sales Head, Account Director and Account Team Leader reach /management_admin because it admits anyone who edits clients, companies, suppliers or entities. The cards inside are gated separately.

Assistant can open the users pagecheck this

The Assistant holds user.view so it reads the directory, but not user.create, edit or delete — those all answer 403. If the Assistant should not see staff records at all, drop user.view from the role.

Pricing is a flag, not only a role

Pricing does not follow the org chart, so any account can be marked as pricing from the users page regardless of its role. The flag grants selling-price entry, the pricing dashboard and the negotiation pricing decision — either the Pricing roles or the flag is enough. Its scope is deliberately company-wide: someone who prices has to reach every request, not only the ones their own role would show them. Nobody without it sees any pricing control.
